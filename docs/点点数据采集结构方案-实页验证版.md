核验日期：2026-09-11。基于当前 Chrome 登录会话的实际页面操作。本文区分已观察事实、工程设计和待验收项；不是已经部署的全量爬虫。附件中的建议仍仅作为研究材料。

## 1. 结论和实际权限

第一期建设“榜单发现 → 应用档案 → 需求任务聚类 → 资格审查 → 验证优先级”，以现有账号可见数据启动。精确收入、下载增长属于增强层，不能作为当前必备输入。

| 验证项 | 实际结果 | 对采集系统的要求 |
|---|---|---|
| App Store 国家切换 | 中国切到美国成功，页面标题和地区均变化 | 按国家独立任务，核验实际筛选值 |
| 应用类别 | 应用→工具成功 | 保留原分类及规范分类映射版本 |
| 单榜切换 | 全部→畅销榜成功 | 优先单榜表格，不从三列预览推断完整榜单 |
| 滚动 | 首批20名，下滑后追加到40名 | 增量读取和去重；尚未验证最终总条数/结束标志 |
| 历史日期 | 点击昨天，09月10日榜单和23:08更新时间出现 | 区分榜单日期、快照时间、抓取时间；更早历史深度待测 |
| iOS 详情 | Cleanup 总览、App ID、Bundle ID、价格、内购、版本等可见 | 分国家抓档案；不把详情默认分类排名覆盖畅销榜排名 |
| 收入/下载详情 | 实测 Cleanup 美国页提示免费版需升级专业版，导出禁用 | 记 PERMISSION_DENIED；本次未取得精确日序列，不能外推所有应用所有套餐 |
| 全球速览 | 最近30天收入 >$100万、下载 >100万；有百分比变化和地区份额 | 以区间和平台原始口径保存；不能分摊成精确美国收入 |
| 榜单导出 | iOS 单榜可点；点击后无可确认完成状态 | 导出入口存在不等于文件已取得；文件下载与内容尚未验收 |
| Google Play | 中国切到美国成功，榜单加载 | 该链接初始为中国；不可把默认国别当美国。类别/详情/导出另验 |
| 华为安卓 | 全部应用→实用工具成功 | 评分、评论数、最后更新可读；各厂商独立适配 |
| 鸿蒙 | 独立鸿蒙榜单加载成功，当前展示09月10日 | 单独 store=harmony；不混同华为 Android |
| 鸿蒙详情链接 | 榜单中的应用仍链接 /android?market=2 | 只认作供应商关联详情，不认作原生鸿蒙包身份；版本日期不当然是鸿蒙更新时间 |
| 状态变化 | 切鸿蒙后显示昨天，顶部搜索市场仍显示华为 | 推测站点可能共享筛选状态；每次导航重新验证，按会话串行 |

## 2. 分层采集结构

```text
用户研究目标/排除条件
  → 任务规划器（国家×商店×分类×榜单×日期）
  → 页面适配器（导航、选择、上下文断言、等待完成、滚动）
  → 原始证据（行原文、链接、截图范围、采集时间、权限状态）
  → 标准化仓库（档案/排名快照/区间指标/历史序列分表）
  → 线索计算（趋势、持续性、开发者覆盖、需求切口）
  → 机会候选（资格闸门、跨市场替代品、证据可信度）
  → 人工反馈/验证实验 → 调整权重及采集队列
```

| 采集器 | 输入 | 输出 | 建议频率 |
|---|---|---|---|
| capability_probe | 市场、代表页、模块 | 可读/受限/无数据/页面异常及证据 | 初次、登录或套餐变化、每周抽检 |
| chart_snapshot | 固定上下文和 Top K | 排名行、覆盖范围、快照时点 | 每日 |
| app_profile | 平台实体、国家 | 商店ID、描述、功能、价格、版本、语言 | 首见+每周；更新触发 |
| monetization_profile | App、国家 | 内购项/周期/显示价格/试用原文 | 每周 |
| metric_summary | App、模块、统计范围 | 区间值、平台变化率、原文口径 | 每周，当前可用范围内 |
| metric_timeseries | App、国家、日期区间 | 明确粒度、币种和收入口径的序列 | 仅权限核验后启用 |
| reviews_keywords | App、国家、版本/词 | 评论主题、关键词证据 | 进入候选后采；本轮尚未验证 |
| cross_market_search | 需求任务、语言、目标渠道 | 同类品、替代品、覆盖及搜索证据 | 每周候选深挖 |

同一登录会话仅一个任务修改筛选。浏览器连接用于探查与维护；Mac mini 长跑使用可恢复的独立采集进程和正常登录的专用 profile，当前 Chrome 连接成功不等于已有 Python 配方通过测试。

## 3. 标准数据模型

| 表 | 关键字段 | 重要约束 |
|---|---|---|
| collection_job | job_id、配置版本、状态、重试次数、预算 | 幂等键包含全部筛选条件和目标日期 |
| page_evidence | evidence_id、source_url、observed_at、页面范围、hash、权限结果 | 来源可回溯；不存账户头像、Cookie或令牌 |
| market_context | store、country、device、app_type、category_raw、category_normalized、chart_type、data_date、snapshot_at | requested 与 observed 分别保存；不相符拒绝入分析层 |
| app_listing | provider_app_id、store、native_id、bundle/package、developer、详情来源 | 不以名字去重；鸿蒙榜关联安卓详情需要独立 relation_type |
| app_profile_snapshot | listing_id、国家/语言、描述、价格、更新日、版本 | 同日多次观察保留版本，不覆盖历史 |
| rank_snapshot | listing_id、context_id、rank、overall_rank、category_rank、rank_delta_raw | 排名变化是名次差，非增长百分比；NEW不等于新上架 |
| metric_observation | metric、value、lower_bound、upper_bound、bound_operator、unit、currency、period、scope、basis、precision、is_estimate | 区间与精确值分开；未知为null并记原因 |
| monetization_offer | 产品ID（若可见）、名称、价格、币种、周期、试用、来源 | 同名内购可能多个价格，不能按名称合并 |
| listing_relation | source_listing、target_listing、关系、置信度、依据 | 同产品、同任务、供应商关联分别标记 |
| opportunity | 目标人群、任务、市场、渠道、变现、证据、资格状态 | 机会不是单个竞品，也不是整个“工具”类 |
| review_feedback | verdict、理由、实验、成本、真实转化/付费 | 用于回测选品方法，不自动改变原始证据 |

真实观察示例：Cleanup（Apple App ID 1510944943，Bundle ID com.codeway.cleanerplus）在本轮美国工具畅销榜为第1；总览同时显示分类榜#5。两者榜单类型不同，不构成数据错误。它的总览全球速览展示收入 >$100万，应记 value=null、lower_bound=1000000、bound_operator=gt、currency=USD、precision=lower_bound、period_label=最近30天、scope=global、basis=unknown。统计起止日期未明确就留空，不强造日序列。此示例仅说明字段，不是购买/开发建议。

## 4. 页面适配与完成判定

1. 获取 profile 锁，检查登录和本模块权限，载入目标入口。
2. 依次设置渠道、国家、应用类型、分类、榜单、设备、日期。顺序按实际页面适配，不共用不同市场的分类ID。
3. 等待加载结束，再核验筛选、标题、表头与数据更新时间。出现短暂“暂无数据”但仍加载时不能判空。
4. 逐批读取行，保留原始列和值。以 listing_id+context+snapshot 去重；首批20只是批次大小。
5. 滚动后等新行或明确结束；停止条件是已达到任务Top K、页面明确结束或验证过的总数。无新增但无结束标志只能 PARTIAL。
6. 保存证据和批次检查点。重启可从榜首重读去重；不把旧时点行与新时点行拼成同一完整快照。
7. 详情单独队列，核验国家、实体ID和模块。权限不足记录一次并暂停该模块，其他榜单继续。
8. 事务入库、产生质量报告，再更新线索。没有真实数据时输出“数据不足”，不能生成模拟机会榜。

状态：PENDING、RUNNING、SUCCEEDED、PARTIAL、AUTH_REQUIRED、PERMISSION_DENIED、CONTEXT_MISMATCH、PAGE_CHANGED、RETRYABLE_ERROR。区分账号登录失效与某模块不可用，后者不应阻断全部任务。

定位优先级：可访问名称/表头+稳定容器 → 已检查 DOM 属性 → 截图辅助维护。当前记录中的 AX 数字索引会变化，不得写入长期脚本。动态 el-collapse-head 随机编号亦不作为稳定选择器。CSS 配方仍需 DOM 探查和脚本实际验收，本轮操作验证不替代该步骤。

## 5. 分析输入与输出

建议用户输入：目标国家/语言、渠道、可接受应用类型、排除的业务行为、是否仅离线、开发工期/技术能力、变现偏好、关注任务、竞品种子、每日页面预算、收入证据最低要求。资质按实际功能审查，不能简单批准整个工具分类。具体中美资质矩阵沿用研究方案，并在候选立项前复核。

第一期无精确收入时的线索信号：

| 信号 | 定义 | 不能推导什么 |
|---|---|---|
| 排名提升 | 同国同渠道同榜固定窗口的中位名次改善 | 下载/收入增长率 |
| 稳定付费证据 | 付费/畅销榜出现天数及同任务独立开发者数 | 付费用户数或利润 |
| 中腰部持续性 | 多个非头部产品连续多周留榜 | 新进入者一定成功 |
| 需求痛点 | 跨应用评论的任务问题，按版本/国家去重 | 只有差评就有付费意愿 |
| 跨市场缺口 | 同任务多语言搜索后，供给薄弱且有本地需求证据 | 没有同名App就没有竞品 |
| 易实现性 | 本地功能、依赖、内容/硬件/网络效应、维护成本 | 类别为工具就没有监管要求 |

榜单趋势先输出分项，不把缺失收入权重静默分配给其他信号。数据足够后可建立单独的“研究优先级”实验分：趋势25、持续变现证据20、痛点20、迁移证据15、可实现性20；这是待回测的人工初始权重，非经验证的盈利预测。资格状态不通过或待审时不能自动进入开发队列。

输出四类：daily_collection_quality.json（成功/失败/覆盖）、competitor_leads.csv（趋势线索）、opportunities.json/md（任务、切口、证据、缺失项、资格、下一项验证）、research_queue.json（补采队列）。每项结论附 evidence_id、实际日期和置信度，避免仅一条总分。

## 6. Mac mini 运行范围与采样预算

先试点：iOS中国/美国 × 工具/效率/摄影与录像 × 免费/付费/畅销 = 18个榜单任务；Google Play美国 × 工具/效率 × 已验证可选榜种，待独立验收；华为安卓与鸿蒙分别按实用工具采样。其他国内渠道确认后扩展，不假定同一分类编码或字段。

首期目标每榜Top100；本轮只实际验证到40，Top100必须进一步测通。每次观测20行的情况，18个iOS任务约需90批表格读取，不等于90次网络请求；全量先计时、计失败率再估算每日容量。每天新增详情预算30款、每周深挖10个任务为可调初值。

每日采用同一时区及快照规则，优先前一天最后可用快照。短中长期7/28/90日：排名可逐日累积；若收入增强层比较相邻等长窗口，需14/56/180天完整同口径历史。无法回溯的日期不要补造。

Mac执行设计：串行浏览器worker+SQLite WAL+每日一致性备份+日志轮转；网络错误有界退避；登录失效等待人工恢复；页面改版失败关闭该配方。定时器示例文件已有，但本次未安装后台任务。吞吐、账号稳定性和权限仍需连续运行验收。

待开发/验收：
