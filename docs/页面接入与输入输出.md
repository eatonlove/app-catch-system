更新时间：2026-09-11。**后续实页验证已完成一轮，最新事实和权限限制见《点点数据采集结构方案-实页验证版.md》；以下早期接入契约保留，CSS配方仍待验收。**

早期状态：截图＋用户确认：账号可访问 App Store 全球、Google Play 全球、国内安卓榜单；Chrome 已打开页面。截图显示国家、榜单类型、热门分类筛选、设备、日期，以及免费/付费/畅销榜等入口。这些是视觉可确认信息，DOM、滚动机制、详情字段/历史权限仍待实页核验。

## 1. 先核验哪些页面

| 顺序 | 实页检查 | 输出证据 |
|---|---|---|
| 1 | App Store 中国区某一分类、固定日期、单一榜单 | 控件/行/链接结构、筛选文字、首尾页行数 |
| 2 | 同设置改美国，确认国别切换实际生效 | 国家校验、产品/排名变化 |
| 3 | 下滑/翻页，观察列表追加还是虚拟列表替换 | 滚动容器、结束/加载标志、稳定实体 ID |
| 4 | 点击一款应用详情及下载收入入口 | 详情 URL、国家/日期/设备、字段名、数值口径与历史深度 |
| 5 | Google Play 同样检查 | 独立配方；不能假设 DOM 与 iOS 相同 |
| 6 | 国内安卓选择具体商店 | 独立商店 ID、指标可用性、无法取得字段 |

同一榜单里，付费榜≠付费人数榜；畅销排名≠收入数字。截图可见的 ¥30.00 是展示价格，不能标作收入。顶部 API 按钮也不能证明当前套餐具有 API 权限。

## 2. 页面配方

`configs/recipes/*.json` 当前是未核验模板，空定位符不会执行。必须依据 `inspect` 得到的实际 DOM 填写：

| 字段 | 用途 |
|---|---|
| verified / verification_evidence | 实页审核标记及对应清单/截图路径；不能只有布尔值 |
| start_url | 实际榜单 URL，不推测站点 URL 参数含义 |
| scope_selector | 仅定位当前榜单区域，避免其他榜单/账号区域混入 |
| ready_selector | 已完成加载的正向标志 |
| auth_selectors | 实际登录失效/验证码遮罩定位，避免匹配导航栏的普通“登录”文字 |
| steps | 顺序 click/fill/select/wait，仅做页面筛选和导航；禁止放付款、账号设置等动作 |
| context_guards | 七个维度分别校验当前页面：market、country、store、device、category、chart、data_date |
| rows_selector / fields | 每行与行内字段相对 CSS 定位；name＋listing_key/detail_url 必需 |
| metrics | 展示字段→指标名、单位、币种、口径、范围、期间、估算属性 |
| next_selector / scroll_selector | 二选一或窗口滚动；分页下一页必须与真实控件对应 |
| end_selector / expected_count | 真实结束标志或已确认应采行数；上限不是结束证明 |
| max_pages / max_rows | 采集预算，触顶结果为 PARTIAL |
| detail | 详情容器/字段、导航步骤、最多检查数量；默认仅保存文字证据 |

字段定位结构示意（定位字符串是占位说明，不是点点实际定位）：

```json
{
  "fields": {
    "name": {"selector": "实测的行内名称定位"},
    "detail_url": {"selector": "实测的行内详情链接定位", "attribute": "href"},
    "rank_text": {"selector": "实测排名定位"}
  },
  "metrics": [
    {"field": "rank_text", "name": "rank", "unit": "position",
     "currency": null, "basis": "observed", "scope": "chart",
     "period": "snapshot", "is_estimate": false}
  ]
}
```

目前不自动识别 CSS selector。探查文件给出实际 ID/classes/role/文本/链接，接入人员需据此配置并验证稳定性，页面变化时重新核验。上下文校验的 `equals` 支持 `{data_date}` 等 context 模板；中文“中国”对应 country=CN 的映射需明确写进已核验配方。若某维度不在可见页面明确显示，不能猜测放行，应增加可验证的 UI 导航/标志后再采。

## 3. 采集输入

`context.json` 示例：

```json
{
  "market": "appstore", "country": "US", "store": "appstore",
  "device": "iphone", "category": "工具", "chart": "grossing",
  "data_date": "2026-09-11"
}
```

market 可选 appstore/googleplay/android_cn。国家用 ISO 两字母；“全球”是账号覆盖能力，不是 country。日期和收入发布延迟由来源事实校验。每个商店/类别/日期对应不同上下文。

## 4. 采集输出

```text
data/runs/<run>/
  checkpoint.json  # 状态、发现记录、原因；不能替代有效 bundle
  bundle.json      # 标准化榜单与证据；成功或明确部分结果
  chart.png        # 可选：当前榜单范围截图
  details/*.json   # 详情文字，默认 context_verified=false，不直接参与增长
```

`bundle.json` 主要字段：schema_version、source、source_url、collected_at、finished_at、context、context_verified、status、rows、recipe_hash、pages_seen、completeness_note。每行包含 listing_key、name、detail_url、raw_fields 和 metrics。

每条 metric 必须有 name、value、raw、unit、currency、basis、scope、period、is_estimate、missing_reason。value 保存十进制字符串或 null；没有收入就没有收入指标，不用价格/榜位反推。大于/小于/区间展示值不转成精确量。

详情页面目前只留文字证据。未来要扩展历史曲线解析，需取得真实表格或导出结构、逐日口径和详情上下文，再生成多份按 data_date 的 bundle；不能将页面“近30日收入”当成当天收入。

## 5. 分析输入与输出

输入文件 `configs/analysis.example.json` 要明确市场、国家、商店、设备、类别、榜单、指标、币种、净毛口径、收入范围、截止日、窗口与低基数阈值。该文件 net/iap 是示例参数，不代表已经确认点点字段口径。

输出 `analysis.json`：

```text
kind = competitor_growth_leads_not_opportunity_rank
data_status = AVAILABLE | NO_COMPARABLE_DATA
request = 完整分析条件
excluded = 不可比口径/部分采集计数
leads[] = 应用身份、各窗口增长/完整度/不可计算原因、证据URL、UNREVIEWED资格
```

同一结果同步导出 CSV 与 Markdown。CSV 对第三方文本做公式前缀防护。增长只对完整日序列计算，当前版本比主设计文档的 90% 覆盖策略更严格：要求比较窗口 100% 齐全，以减少早期误判。零可参与计算，null 不补零。收入负值需核验退款口径，不计算增长。

供后续机会系统消费的建议流程：leads→任务聚类→目标市场需求核验→行业资格→机会评分→验证实验。当前代码不会把增长线索直接转成“可上架”“值得立项”。

## 6. Mac mini 调度

`run-plan` 使用单 profile 文件锁，成功的同配置/同数据日期任务跳过；可用 `--force` 有意重采。首次实页成功之前保持所有 jobs.enabled=false。计划存在 data_date 则固定日期；删除后才按 lag_days 生成请求日期。建议调度机器时区为 Asia/Shanghai。

`ops/com.appcatch.collect.plist.example` 是待填绝对路径的模板，未安装到系统。实际启用前要完成：实页配方、专用浏览器正常登录、三个市场小样本、连续运行/睡眠重启测试、数据截止日确认。首次不要 headless；验证专用会话无头可用后再调整。

失败记录在 checkpoint 和 last-plan-run.json；程序不绕过验证码、不改变 Chrome 安全设置。当前版本不含自动退避/所有 429 检测；网络/结构错误记录并由后续计划或人工重试，仍需实页验收完善。没有真实窗口样本前，不承诺 24 小时无人值守稳定运行。
