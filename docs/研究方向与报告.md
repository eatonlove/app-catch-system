# 研究方向与报告使用说明

## 查看采集数据

工作总览 → 最近采集任务 → 查看数据。详情页展示任务状态、日期、国家/渠道/榜单、条数和采集时间；可按应用名或开发者搜索。点击应用名或“查看字段”可查看所有已采集原始列、标准化指标以及点点详情链接。没有采到的指标显示未知，评论数不混作评分数。部分结果单独标明，不加入完整榜单分析。

## 打开完整报告

机会研究列表的“新页面查看”会打开独立标签页；新建研究后进入独立报告网址，排队和运行状态每5秒更新。网址可刷新、收藏和再次访问，仍需登录。报告包括AI结论、未知项、竞品趋势、证据附录、实际提示词和模型信息；可导出JSON或打印保存PDF。旧报告仍可打开，缺少历史提示词时不伪造。

## 选择AI分析方向

直接选择AI分析方向即可自动启用模型研究；也可先切换分析方式。切回无模型费用的趋势分析会清空AI方向，方向选择框始终可操作。模板来自用户最初的需求及两份选品SOP，但不把附件中的阈值、收入倍率、资质或营销建议当事实。

|方向|研究重点|
|---|---|
|综合选品|需求、竞争、变现、资格和小团队可执行性|
|增长竞品挖掘|7/28/90日同口径变化，付费和收入证据缺口|
|跨市场机会|中美、App Store/Google Play/安卓/鸿蒙的迁移假设|
|低资质门槛|功能×国家×渠道×主体，区分基础材料与专项许可|
|SEO / ASO 长尾机会|人群＋诉求＋场景、搜索意图与流量验证|
|痛点与竞品弱项|差评、功能、新手流程、付费墙的可验证弱项|
|小团队 MVP 与变现|单任务核心功能、收入模式假设、最小实验与停止条件|

提示词可直接预览；补充要求可输入或从UTF-8 txt/md导入，最多6000字符。导入只填充输入框，提交前可修改，不自动执行文件内容。提交时系统保存方向/版本/完整system prompt快照，模型收到的是真实保存的提示词；不同提示词使用不同缓存。全部模板保留相同JSON和证据约束，最多返回5项。

当前模型输入上限15条证据，报告展示范围最多200项；跨市场方向轮流抽取不同已观测国家/商店的证据，其余方向按研究优先序取样。单一市场数据不能证明跨市场空白。数据仍缺收入、评论原文、关键词等时会显示缺口，不联网补造。新方向不会自动改变采集计划；需要补采的证据由后续任务获得。

验证：42项自动测试、PostgreSQL集成、真实页面本地副本的详情/搜索/报告浏览器验证；千问实际方向提示词调用成功并通过输出校验。测试报告只在本地验证库，不写入线上业务报告。

## 数据来源与“没有候选”的解释（更新）

研究页先选择具体采集批次，完整与部分结果分别标示；预览展示日期覆盖、条数、7/28/90日可比记录数、缺少的字段。模型输入可选最多15或30条，受40000字符上限限制，实际应用名单可展开核对。默认选择完整批次，部分批次不会被悄悄纳入。提交时冻结来源ID，排队期间后来完成的采集不会加入本次报告。

报告顶部展示“本报告用了哪些数据”：每个批次的记录数与AI实际读取数、日期、链接、缺口和补采建议。旧报告根据已保存证据重建；历史未保存的AI输入范围显示未知，旧模型结论不重写。可点击“按这些来源重新选择研究”回到已选来源的研究页。

“无候选”不等于市场不存在机会。只有一天数据时不能证明7/28/90日增长；没有收入、付费和用户评论时，不能证明盈利或痛点。新版提示词允许从已观测类别与任务提出最多3条明确标注的待验证线索，并要求summary、data_gaps、next_steps解释结论及验证办法；不要求证据不全时一律空数组，也不为了出结果编造数据。

本次修复通过46项测试和PostgreSQL验证，使用真实采集副本的浏览器验证来源勾选/AI名单/旧报告解释，并完成真实模型输出结构验证。测试报告只在本地库。
